Why do queued rounds stall after a runner reconnect?

Waiting on youRead-only · enforced by runnerAsked by Andrew B. · finished 4 min ago
Read46 files · 3 logs
Rounds2
Duration6m 12s
Cost$0.84

Report

What the analysis found, with the evidence it read.

Summary

On reconnect the runner registers with a new session id, but the dispatcher keeps rounds bound to the old one until its 90 s heartbeat expires. Rounds dispatched in that window are acknowledged by nobody and wait for the stale-round sweep, which runs every 10 minutes.

Findings

  1. Rounds stay bound to the dead session. apps/api/src/runners/round-dispatcher.ts looks up the runner by session id, not by runner id; the gateway never rebinds on runner.hello.
  2. The backoff resets on a half-open socket. apps/runner/src/connection/backoff.ts treats a TCP connect as success before the handshake, so a flapping network reconnects every 500 ms.
  3. Nobody sees it. Fleet shows the slot as Running throughout; the 3 logs read show 11 such windows in the last week.
