  1. 1

    Create and filter by kind C-510

    "New" opens a menu: Code card or Task for a person. A Kind select in the Toolbar filters the Board, stored in the URL like the other filters.

    Button solid · Menu · Toolbar Select

  2. 2

    A clean task face C-510

    No agent, branch, cost or demo chip: a task never runs on a slot. A square "Task" tag, the assignee's initials, checklist progress and a StatusPill (Not started, Waiting on you, Done). The bar is neutral; it turns ok only when complete.

    board-card · Badge shape=square · StatusPill

  3. 3

    Raised by a worker C-511

    When a stuck worker raises the task, the face names the slot and the card it came from. Person-made tasks have no such line.

  4. 4

    Code cards wait on a person C-509

    Dependants use the existing statuses: Blocked if not started, Session paused if its worker paused to wait. "Waits for C-530" opens the task.

    StatusPill blocked / paused

  5. 5

    Task sheet C-510

    Opens from the card, same Detail Sheet as code cards, with title, status and age first.

    Sheet (glass-strong)

  6. 6

    Resume promise C-511

    An info Banner, only for worker-raised tasks: Done resumes the paused session, so the person knows what the click does.

    Banner info

  7. 7

    Where it came from C-513

    Board, Telegram (/task or the assistant) or MCP card_create. A task made in Telegram can be marked done from the same message.

    KeyValueList

  8. 8

    Delivered to C-512

    The assignee's Inbox plus their enabled channels. A ✓ means delivered; a failed channel shows a warn Badge with a retry.

  9. 9

    Optional checklist C-509 · C-510

    Items tick in place and save instantly; the add row follows the glob-list pattern from Settings. A task without items shows the add row only.

    Checkbox · Input · Button glass

  10. 10

    Waiting on this C-509

    Every dependant and what Done does to it: Resumes (a paused session) or Starts (a queued card).

  11. 11

    Mark done C-509

    The sheet's one solid action. With open items it asks first in a ConfirmDialog. Done satisfies the dependants, and the Board moves them by itself.

    Button solid · ConfirmDialog
