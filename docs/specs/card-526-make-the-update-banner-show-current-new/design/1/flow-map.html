From “an update exists” to “the command is on the clipboard”

An admin sees how far behind the install is, opens How to update and copies a command to run on the server. The web app never runs the upgrade.

→

GET /admin/updates reports an update: running 0.17.1 → 0.18.0

2How to update open
→

Backup first, then three ways: Compose, install.sh, a pinned version

3Command copied
→

The button reads ✓ Copied for 2 s and screen readers announce it. The demo ends here.

4Dismissed

✕ hides the banner in this browser until a newer release, as it does today

Branches

backCollapse

“How to update” toggles. Closing it returns to step 1 without moving the banner.

skipDismiss from any step

✕ goes to step 4 from step 1, 2 or 3.

errorClipboard blocked

On plain HTTP, or when permission is denied, the button reads “Select to copy” and selects the command text. Nothing is lost.

skipNo banner at all

No banner when the install is up to date, the check is off, no answer has come back yet, the viewer is not an admin, or this release was dismissed.

loopNext release

A version newer than the dismissed one starts the flow again at step 1.

outLinks leave the app

The release notes, the docs Upgrade page and the Backup page open in a new tab.
