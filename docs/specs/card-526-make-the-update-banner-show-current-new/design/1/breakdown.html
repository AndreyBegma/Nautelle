C-526 · Breakdown

What the steps share

The components, states and rules behind the update banner. Everything comes from glass-ui (ADR-0011). Anything glass-ui lacks is added to glass-ui, not to apps/web.

Components

In the order they appear in the banner.

Banner glass-ui · existing

tone="info" with onDismiss, as today. The title is “Nautelle update available”. It is mounted in the app shell and shown to admins only.

VersionChange glass-ui · new
Running 0.17.1→Latest 0.18.0

Props: from and to, plus optional labels. It draws two mono Badges, danger then ok, joined by a lucide arrow. Both badges carry text labels and the pair reads aloud as “Running 0.17.1, latest 0.18.0”.

Disclosure glass-ui · existing

The trigger is a glass-sm “How to update” button with a chevron and aria-expanded. It starts closed every time the banner mounts. On a phone it spans the full width.

CodeBlock + copy glass-ui · extend if missing
Copy→✓ CopiedorSelect to copy

Whether CodeBlock already has a copy button is [Unknown]. If it does not, a copyable prop is added to glass-ui. The button sits pinned at the top right while the code scrolls under it. It copies exactly the block's text.

Backup line warn tone

A database icon, “Take a backup first.”, the note that downgrading is not supported, and a link to the docs Backup page. It uses the warn tone because this is a caution, not an error.

Links

Release notes opens release.url. Upgrade guide opens UPGRADE_GUIDE_URL. Back up an install opens docsUrl('/operations/backup/'). All three open in a new tab with rel="noreferrer".

Rules

No upgrade from the web app

There is no “Upgrade now” button and no endpoint for one. The server cannot restart its own compose stack, and a runner may live on another machine. The banner has no solid button, so the page keeps its single primary action.

Data

The data comes from GET /admin/updates, whose ProductUpdateView already includes current. ProductUpdateNotice gains a current prop next to release. The API and the schema do not change.
